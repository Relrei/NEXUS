# NEXUS 設計思想ブリーフ（実装AI = Kimi 2.6 向け・ゼロから再実装）

これは「何を・なぜ」だけの設計思想。**見た目テーマは一切指定しない**（落ち着いて常用に耐えること以外は自由。生物的/SF的な装飾を前提にしない）。
あなた（実装AI）はこれを土台に NEXUS を一から作る。

## 1. 一行コンセプト
**「考える道具」ではなく「梱包する道具」。** 散らばった素材を集め→束ね→AIや自分に渡せる形に鋳造する、個人の倉庫/図書館。

## 2. 解決する課題（最重要・存在理由）
- 制作/バイブコーディング中に同じ確認・検索を何度も繰り返す。忘れる。方向性がまとまらない。
- 調べて満足し、また不安で「まだ無いか」調べ直す無限ループ（ADHD的な不安駆動）。
- メモやファイルを作るのが面倒で放置する。
- → **我慢でなく「再調査が要らなくなる」仕組み**で消すのが目的。気合いや根性で解決させない。

## 3. 中核思想
- ワークフロー：**発散(アイデア)→収集(素材)→収束(束ね)→鋳造(梱包)**。＝ `Source → Transform → Output` のデータフロー。
- 本命の出口は**「実行」でなく「梱包(packaging)」**。世界に撃ち込まない。代わりに「AIが一発で食えるコンテキスト塊（例：`CLAUDE.md` ＋ `spec.md` ＋ `refs/` のファイル一式）」や「自分用の設計ブリーフ」を**生成して吐く**。これがこのアプリ最大の独自性。
- **実行モデル＝pull・純粋・無時間**。自動実行・スケジューラ・通知・SNS投稿などの副作用は持たない＝安全で追いやすい。
- **鮮度2層**：`Cold`（一度調べたら変わらない＝倉庫・永久キャッシュ・大半）／`Hot`（リアルタイム性・TTLで再取得対象）。

## 4. 不安を消す機構（設計の肝・ここを外すと意味がない）
- 調べた物を**可視の物体**にする＝「もう調べたっけ？」を「目の前にある＝調べ済み」に変える。
- `Cold`＝**確定（ロック）**にして再調査の対象から機械的に外す（`Hot`だけが再取得していい対象）。
- **重複検出**（内容ハッシュ）で「もう持ってる」を即提示。
- **Outputに必要ポート＝完了条件**を定義 → 全部埋まれば「揃った＝終わり」が確定。無限の収集を有限にする。
- **孤立警告**：どのOutputにも繋がっていない収集物を薄く表示（集めるだけの自己目的化を防ぐ）。
- **摩擦ゼロのInbox**：とりあえず投げ込む（テキスト入力＋Enter／ドラッグ＆ドロップ／ペースト／書き散らし）。分類は後でいい。「作るのが面倒」を消す。

## 5. 情報設計（重要：一体型にしない）
- ★**1画面に全部を詰め込まない**（見づらくなる、という実体験からの要件）。
- **ホーム＝エクスプローラー（地図）→ 場所ごとに分岐**するハブ＆スポーク構造。
- ゾーン例：**インプット / 画像倉庫 / ノート倉庫 / リンク / Output工房**。各ゾーンは独立した画面で、ホーム地図から入って戻る。
- 各アイテム・各ゾーンは状態（Cold / Hot / 確定 / 未充足）を持ち一目で分かる。

## 6. データモデル
- `nodes(id, type, params, cached_output, dirty_flag, freshness, fetched_at)` ／ `edges(from_id, from_port, to_id, to_port)`。
- **同一性＝安定ID**（位置や名前ではない）。座標(x,y)は表示用の飾り。rename/移動で参照が壊れないこと。
- **線に流す型は4つに絞る**（増やすと“繋がらない地獄”になる）：
  - `Text`（アイデア・メモ・制約・プロンプト断片）
  - `MediaRef`（画像/動画＝**パス＋サムネ＋メタのみ**。実体は content-addressed な別poolに置き、線に中身を流さない）
  - `Reference`（URL・収集物）
  - `Record`（構造化された束＝タスク・仕様項目）
- ジョブキュー・実行履歴・冪等キーは**不要**（撃ち込まないから）。

## 7. プラットフォーム / 技術（制約）
- **Linux / Android / iPad で動く**こと。開発機は Linux（Mac無し）＝iPadネイティブは作れない。
  → **Web / PWA**（インストール可・オフライン可）が必須解。
- **ローカルファースト**：データは端末内（IndexedDB / SQLite-wasm 等）。クラウド前提にしない＝データは本人所有。
- **自前公開**：静的ビルドを任意のホストに置けば全端末からURLで使える。端末間同期は**後付け・任意**（Syncthing / git 等）。
- 個人用・単一ユーザー。認証やマルチテナントは作らない。

## 8. MVP と優先順
1. **摩擦ゼロ捕捉 → 倉庫（可視保存）→ 検索**（日本語は語境界が無いので **substring 一致＝漢字1字でも拾う**）。
2. **ホーム地図 → ゾーン分岐**（ハブ＆スポーク）。
3. **ノードグラフ ＋ 梱包Output**（`Source→Transform→Output`・必要ポート＝完了条件・`CLAUDE.md+spec+refs/` を鋳造）。
4. 端末間同期（任意・後）。

## 9. やらないこと（非目標）
- 自動実行・スケジューラ・SNS投稿・通知などの**撃ち込み系**。
- マルチユーザー・クラウドSaaS化。
- 常用の落ち着きを損なう**過剰な装飾テーマの強制**（見た目は自由だが、毎日使えて疲れないことが上位条件）。

## 10. 成功の定義
**「散らばりと不安を、検索ではなく“確定した倉庫”で終わらせ、その倉庫からそのまま制作に渡せる」。**
ユーザーが同じことを二度調べず、「もう揃った」と安心して手を止め、その素材束をワンアクションで制作（AIへのプロンプト/ファイル一式・自分用ブリーフ）に渡せたら成功。
